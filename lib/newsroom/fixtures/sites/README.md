# Site fixtures — three real newsrooms, captured

Everything in this directory was fetched by hand, once, on **2026-08-06**. Nothing here is
regenerated by the test suite — `lib/newsroom/charter-fixtures.test.ts` reads these files through
`load.ts`, never the network. A fixture is a dated measurement: the sites will change, these files
will not, and that is the point — they pin what `proposeCharter` found on that date, so a later
task can prove what it changed.

No file here was truncated. The largest (`heidi-news.css`, 557 642 bytes) is small next to other
committed assets in this repo (several MB video/geojson fixtures already live under `skills/`), so
keeping it whole removed the one real risk of trimming: a cut CSS file can silently drop the very
custom property or `@font-face` rule the measurement depends on, which would mean testing against
a fabricated site rather than the real one.

## Why these three

- **`heidi-news`** — the newsroom this whole feature was built for, and the one whose reading
  exposed the defect this chantier fixes (spec `docs/superpowers/specs/2026-08-06-charter-reads-real-sites-design.md`).
  It serves its CSS from its own CDN, `heidi-17455.kxcdn.com` — a different host from
  `www.heidi.news` — which today's same-host filter in `stylesheetHrefs` drops entirely. The
  fixture captures both the page and that CDN stylesheet, so this chantier's task 2 (lifting the
  filter) has something real to unblock.
- **`therecord-media`** (`https://therecord.media`) — a Next.js application: its CSS ships as
  hashed webpack/Tailwind-utility chunks, with no `<meta name="theme-color">`, no `--brand` /
  `--primary` custom property, and no masthead SVG naming a colour. It proves the *"or one that
  carries no brand"* half of the brief's second site: its stylesheets ARE same-host (so today's
  filter is not what blocks it), and the extraction still correctly finds nothing the site itself
  labelled as its house colour — `confidence: "inferred"`, honestly. It is a real example of the
  case the spec's §3.3 "rendered mode" is aimed at: a site that builds its presentation in
  JavaScript rather than declaring it as data a static fetch can read.
- **`restofworld-org`** (`https://restofworld.org`) — a plain, honest declaration:
  `<meta name="theme-color" content="rgb(36, 46, 247)">` (a `theme-color` expressed as `rgb()`,
  not hex — exercises `parseCssColour`'s non-hex path) matches a `--primary: #242EF7` custom
  property in its own stylesheet almost exactly, and its typography is named for what it is
  (`Moderat`, `GT Sectra`) rather than hidden behind a generic system-font stack. This is the
  measurement working as designed: a newsroom that says what its colours are, and the extractor
  believing it at `confidence: "declared"`.

## Capture commands

`heidi-news` used the command given in the task brief verbatim:

```bash
bun -e '
const save = async (name, url) => {
  const html = await (await fetch(url)).text();
  await Bun.write(`lib/newsroom/fixtures/sites/${name}.html`, html);
  const href = /<link[^>]+rel="stylesheet"[^>]+href="([^"]+)"/i.exec(html)?.[1];
  if (href) await Bun.write(`lib/newsroom/fixtures/sites/${name}.css`, await (await fetch(new URL(href, url))).text());
  console.log(name, html.length, href ?? "no sheet");
};
await save("heidi-news", "https://www.heidi.news");
await save("therecord-media", "https://therecord.media");
await save("restofworld-org", "https://restofworld.org");
'
```

Output (2026-08-06):

```
heidi-news 126938 https://heidi-17455.kxcdn.com/assets/heidi-8cc89e35b42fa6e471837638cc00c4c708e4b33db81e43c9de7882418a2d2fff.css
therecord-media 91189 /_next/static/chunks/3t3yknc51puyw.css
restofworld-org 177444 /wp-content/projects/code/promo/homepage-donate-promo/style.min.css?3
```

**`restofworld-org.css` was re-captured**, deliberately deviating from that output. The brief's
regex requires `rel="stylesheet"` (double quotes) to appear before `href="…"` in the same tag;
`restofworld.org`'s actual stylesheet link uses single quotes
(`<link rel='stylesheet' id='style-css' href='…page.min.css…'>`), so the naive regex skipped it
and matched a much later, unrelated 473-byte donate-widget stylesheet instead — carrying no brand
signal at all. Re-captured with the project's own (quote-agnostic, host-agnostic since this
chantier) stylesheet resolver instead of a one-off regex:

```bash
bun -e '
import { stylesheetHrefs } from "./lib/newsroom/charter-fetch.ts";
const url = "https://restofworld.org";
const html = await Bun.file("lib/newsroom/fixtures/sites/restofworld-org.html").text();
const href = stylesheetHrefs(html, url)[0];
const css = await (await fetch(href)).text();
await Bun.write("lib/newsroom/fixtures/sites/restofworld-org.css", css);
console.log(href, css.length);
'
```

Output: `https://restofworld.org/wp-content/themes/orbis/static-assets/dist/css/page.min.css?ver=gei88-page 534984`

`therecord-media.css` needed no re-capture — its first stylesheet link is double-quoted, so the
brief's naive regex already resolved to the right file
(`https://therecord.media/_next/static/chunks/3t3yknc51puyw.css`, 69 190 bytes on disk).

Each site's second (or later) linked stylesheet was **not** captured — only the first, matching
what the capture command above does. For `restofworld-org` that is a real trade-off (a small
donate-widget stylesheet was left uncaptured); for `heidi-news` and `therecord-media` the
uncaptured sheets are not the design system either, so nothing material was left out.
