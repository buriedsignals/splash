# Tooltip a11y (systemic hover-contrast) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Grounded by a 2-agent
> scout (tooltip code + harness gap). Fixes a systemic WCAG bug: 10 chart-native components paint the hover
> Tooltip's series/item NAME in a mark hue on the dark ink tooltip bg → fails 4.5:1 (blue #0072B2=3.36:1 is
> `palette[0]` in every affected chart; black 1.21 Chord; muted 3.27 Bump/Parallel). Out of `snap-contrast`'s
> reach (static-SVG-only, no hover). Scope (Rémy): **patch the 10 in place (swatch pattern) + a hover-contrast
> harness** — NOT the shared-Tooltip 40-migrate (separate DRY follow-up; the harness gives non-regression).

**Goal:** the interactive hover tooltip name renders legibly (≥4.5:1) on all 10 affected charts, keeping the
hue↔series association via a decorative swatch; a mechanical harness fails produce if any tooltip regresses.

**Base:** branch `feat/tooltip-a11y` from main `e754a8a`. `bun run check` green each task.

## Global Constraints
- Bun; English; zero `any`/`@ts-ignore`; no vendor. `bun run check` green at end of every task.
- **Fix pattern (mirror ComboChart.tsx:451-455, the in-repo correct model):** the coloured name becomes a
  **white name + a decorative coloured swatch glyph**:
  ```jsx
  // before:  <strong style={{ color }}>{label}</strong>
  // after:   <span aria-hidden="true" style={{ color, marginRight: 4 }}>■</span>
  //          <strong style={{ color: "#fff" }}>{label}</strong>
  ```
  The `■`/`●` is a **decorative glyph (non-text)** → exempt from the 4.5:1 text rule, so it keeps ANY hue; the
  name renders white (17.4:1 on ink). This preserves the series↔colour link a plain-white name would lose.
- **Controller render-verifies hover tooltips** (produce interactive + Playwright hover a blue/palette[0] mark,
  screenshot) — the failing case is the default/first series.

## Task 2: snap-tooltip-contrast.mjs harness + wire fail-hard + non-vacuity

**Files:** new `scripts/snap-tooltip-contrast.mjs`; modify `scripts/produce.mjs`.

- [ ] `snap-tooltip-contrast.mjs` (mirror snap-a11y.mjs + snap-contrast.mjs shape): load the **interactive**
  singlefile (`file://`, like snap-a11y.mjs:23); `waitForSelector("svg")` + settle (~1700ms); for the first mark
  of each series (per-type selector from snap-a11y.mjs:12-19; hover ~first N≈12 marks), `await mark.hover()` (or
  `.focus()`) → `waitForSelector(".tooltip")`; in `page.evaluate`, for each text node in `.tooltip strong,
  .tooltip span, .tooltip div`: read `getComputedStyle(el).color` + `.opacity`, find the **nearest ancestor with
  an opaque `backgroundColor`** (the `.tooltip` ink — NOT `elementsFromPoint`, because the tooltip is
  `pointerEvents:none`), **composite opacity** into the effective colour, return `{text, fill:eff, bgs:[bg]}`.
  In node, reuse `worstContrast(fill, bgs) < MIN_CONTRAST` from `core/contrast-scan.ts`; collect violations;
  `console.error` each + `process.exit(1)` (same shape as snap-contrast.mjs:95-106). Document limitations in-file
  (hover-N-marks coverage; ancestor-walk bg; opacity composite) matching snap-contrast's honesty comments.
- [ ] Wire into `produce.mjs` right after the snap-contrast call (`:87`): `run("bun",
  ["scripts/snap-tooltip-contrast.mjs"], ...)` → fail-hard via the existing `execFileSync stdio:inherit` `run()`.
- [ ] **Non-vacuity (RED→GREEN):** with Task 1 merged (10 fixed), the harness passes GREEN. Prove it has teeth:
