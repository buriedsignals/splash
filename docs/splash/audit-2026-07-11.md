# Audit qualité splash — flow & résultat (2026-07-11)

> Audit + benchmark + scoring de la pipeline splash. **Méthode** : (1) scoring sur le corpus
> existant Waves 1-7 (42 runs e2e + jugements + vérifs au rendu) + inspection code d'enforcement ;
> (2) fresh benchmark ciblé (3 cas neufs) sur les dimensions faibles ; (3) audit d'enforcement code
> par deux passes indépendantes (orchestration + producteurs). Score par dimension /100 + lettre,
> **gradé sur la force d'enforcement** (mécanique fail-hard vs advisory LLM), pas sur l'intention.

## TL;DR — score global **71/100 (B-)**

| Axe | Score | Lecture |
|---|---|---|
| **FLOW** (orchestration) | **73/100 (B-)** | Épine mécanique fail-hard solide ; gates humains attestés-LLM (non prouvés) ; intention-de-format **empiriquement réparée** (fresh benchmark) mais advisory |
| **RESULT** (visuel produit) | **69/100 (C+)** | Correctness + contraste chart-native exemplaires ; sémantique (titre↔takeaway, palette) meilleure qu'attendu au fresh benchmark mais **non-gardée** ; vidéo non-gardée ; couverture inégale (map-dw le plus faible) |

**La thèse de l'audit** : splash est **fort là où le code garde** (channel→format pinning, tripwires de
correctness, contraste WCAG chart-native, livraison single-format) — B+/A- sur ces axes. Il est **faible
là où seule la discipline LLM garde** (intention de format, titre↔takeaway, palette subject-fit, reveal
vidéo) et **inégal en couverture** (map-dw quasi non-gardé ; i18n appliqué mais jamais gaté ; label-fit du
corps de chart correct-par-construction mais non-vérifié au rendu). La **trajectoire est fortement
positive** : la méthode « feedback→système » convertit chaque défaut en garde mécanique partagée, donc la
surface gardée compose. Les creux résiduels sont exactement ceux **sans levier mécanique propre** +
les producteurs les plus récents/moins balayés + la vidéo.

## Métriques du corpus (Waves 1-7, 42 runs e2e)

- **Taux de livraison : 36/42 (86 %)**. Les 6 non-livraisons : 3 closed-early (registration harness
  a/b/c-capture + heatmap non-atteignable), 1 timeout transient (inflation), 2 turn-cap (seismes hang +
  1). **Complétion-production réelle ≈ 93 %** (hors artefacts harness).
- **Sévérités brutes (tous logs) : 24 critical · 125 major · 212 minor.** ⚠️ **Chiffres trompeurs** : la
  majorité des « critical » sont soit des artefacts harness (`check:deliverable-reached` sur interactif/dw
  closed-early), soit des faux positifs du juge (Wave 7 `numberFormat "0.0%"` — DW append « % » sans
  multiplier, `map-spec.ts:235`, render-vérifié correct). **Critical produit RÉELS ≈ 3-4 sur 42 runs**
  (export-skip W1 corrigé ; timeout W3 ; conformance-workaround W5). Corollaire gravé : **le juge peut
  mentir** — le scoring ne peut pas se fier aux comptes bruts.
- **Trajectoire critical/major par wave** : W1 1/6 · W2 0/2 · W3 2/5 · W4 1/6 · W5 2/3 · W6 0/2 · W7 3/4
  (les 3 W7 = 2 artefacts harness + 1 faux positif → 0 réel). Pas de dérive à la hausse ; les défauts se
  déplacent vers les types/producteurs neufs puis sont gravés au système.

## Forces (à préserver)

1. **Épine produce/export fail-hard.** `assertFormatAllowed` + `freshOutDir` + `producerMismatch` +
   gate de validation composé + `assertShippable` = des garanties qui **ne peuvent pas être skippées sur
   le chemin export**. C'est le socle.
2. **`snap-contrast` (contraste WCAG au rendu réel, les 41 types).** Enhancement mécanique, pas discipline
   — attrape toute la classe label-couleur-mark pour toujours. Modèle à répliquer (map-native, map-dw).
3. **Tripwires de correctness data** (annotation-domaine dw-chart, join-match map, value-axis-0) — attrapent
   des défauts qu'un rendu ne montre pas (annotation *droppée*, carte grise).
4. **Single-format livraison** (post-redesign) — statique/vidéo airtight via `assertDelivered`.
5. **Méthode feedback→système** : chaque défaut → garde partagée → tous les futurs types en héritent. La
   surface gardée compose wave après wave.

## Recommandations (ordre)

1. **P1 + P2 d'abord** (impact haut, mécaniques, petits) : snap vidéo + fail-closed channel.
2. **P3 + P4** (ferment les 2 plus gros trous de couverture qualité) : snap label-fit générique + plancher map-dw.
3. **P5** (i18n gate) — un check simple à fort rendement souveraineté/qualité FR.
4. **P6-P9** = tickets plus lourds (levier sémantique, design palette, feature heatmap, vérif hash).

## Verdict

splash est une pipeline **B-** qui **sur-performe (B+/A-) partout où le code garde** et **sous-performe
(C) sur les axes sémantiques sans levier mécanique**. Ce n'est pas un défaut de conception — c'est la
frontière naturelle de « feedback→système » : ce qui est mécanisable a été mécanisé et est solide ; ce qui
reste demande soit un levier neuf (P1-P5, faisables), soit une décision design (P7), soit accepte de
rester discipline-LLM attrapée par la QA (P6). Pour le livrable bourse (open-source MIT, petites
rédactions), les priorités P1-P5 sont celles qui protègent le plus une rédaction non-équipée d'un défaut
silencieux.
