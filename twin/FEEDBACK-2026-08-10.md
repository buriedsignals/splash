## Owner's rulings, 2026-08-10 — taken after the surveys, binding

### R1 — Map web is LIVE MapTiler, and the delivered HTML carries the key

**This overturns `map-web-discipline.md:357-381`**, which rejected live tiles in writing because they
break self-containment and ship a MapTiler key inside the delivered file. The `ZOOM_SCALE = 1.4`
control over a baked plate is what shipped instead — and it is the out-of-map button B6.14 asks to
remove.

The owner was shown the cost explicitly: the key becomes visible to anyone who opens the article, on
an account billed by usage, and the file stops working without network or an active account. His
ruling, verbatim: *"la carte doit rester interactive tout le temps sinon il n'y a pas d'intérêt
d'être sur le web si on peut pas naviguer dedans. On a le droit d'utiliser pleinement MapTiler. Et
garder l'export du HTML pas grave pour la clé."*

The reasoning is editorial and it is right: **a web map you cannot move through is a picture.** If a
beat pays the cost of being web, it should give what web gives.

So: **map × web uses live MapTiler tiles with its native zoom and pan**, constrained to the
subject's area. The baked plate remains what static and video use. The standalone HTML export
carries the key — accepted, not overlooked. `map-web-discipline.md` must be rewritten to record the
reversal and its cost rather than quietly deleting the old argument.

### R1b — The key never enters the repository, and the delivered one is domain-restricted

R1 put the MapTiler key in the delivered HTML, knowingly. It did **not** cover a second place the
key would land, which the W5/W6 spec surfaced and the owner then ruled on: **the proof beats commit
their HTML**, so a real key would enter git — and the FJM deliverable is an **MIT open-source
release**. A key on a public GitHub repository is scanned by bots within minutes of the push, and
git history keeps it after any later removal.

That matters because MapTiler **invalidates ALL of an account's keys at 100% of its spending
limit** (documented). One abused key blanks the maps in articles that are already published.

So, ruled 2026-08-10:

- **Committed artifacts carry a placeholder**, never a key.
- **`twin-deliver` substitutes the real key** at the moment the file goes to the newsroom.
- **A guard asserts no tracked file contains a real key** — it reddens before the mistake is
  committed, not after.
- **The delivered key is a SECOND, domain-restricted key**, not the development one. MapTiler's own
  documented mitigation: copied elsewhere, it does not work. One nuance to carry into the spec — an
  account's **default key cannot be restricted**, so a dedicated one has to be created.

R1 is unchanged: the map stays live, the key stays in the newsroom's export. This only keeps it out
of the public repository.

### R2 — Export sizes: three fixed for static and video, a RANGE for web

Landscape for YouTube and article-web, portrait for stories, square for social posts. **Charts and
maps both**, one model, no per-family exception — which settles the geo rule 12 tension by making
the target aspect an input the camera takes, rather than a frame the map is cut into.

**Web is not a fourth size.** The owner: *"pour les tailles en web oui ça doit être responsive car
on intégrera ça dans le CMS donc ça fonctionnera un peu comme un composant embed."* Web fills its
container, whatever the CMS gives it. The `export-sizes` survey found the original Splash already
models exactly this (`interactiveAspect: "responsive"` on every channel row), which is evidence the
shape is right — not licence to import it.

## What this feedback is really saying

Read as a whole rather than as 40 items, three things dominate, and they are not beat defects:

1. **Furniture, palette and typeface are not yet the newsroom's.** B1.1–B1.3 repeat on every one of
   the 23 types because they are properties of the CRAFT SKILLS, not of any beat. The palette
   threading landed 2026-08-09 (`readPalette`); typeface and credit placement did not.

   **A note on the word, because it decides the architecture.** An earlier draft of this paragraph
   said "engines". That is the ORIGINAL Splash's shape (`skills/` at the repository root), and
   reaching for it here would propose exactly what this branch refuses. The twin is Tom Vaillant's
   self-contained-skill method: *a skill must stay copy-pasteable on its own, so helpers are
   duplicated rather than imported* — enforced by `no-cross-skill-imports.test.ts`. So the answer to
   "make this true for 23 types" is never "extract a shared layer"; it is **the same change, made
   identically in each craft skill, with a walking parity test proving the copies stay in step**.
   `render-still-parity.test.ts` and `video-helper-parity.test.ts` walk the tree rather than taking
   a list, which is what makes deliberate duplication safe at 20+ copies — and
   `helper-parity.test.ts`'s hand-written list is the standing counter-example: it turned the suite
   red for a correct change, and two agents kept a dead export alive to satisfy it.
2. **Size is not yet a dimension of production.** B2.1 and B3.2 are the same missing idea from two
   sides: a beat is produced at one size today. Static/video need portrait, square and landscape;
   web needs to be genuinely fluid with a mobile form.
3. **Maps are built for one camera.** B4.1 is the largest single piece of work in this file: every
   map beat is tuned to its own extent, and the tool has to hold a city and a planet with the same
   machinery.

Everything in Part A is one further thing: **the journey talks to the journalist about the wrong
subjects, in the wrong order, and sometimes about us.**
