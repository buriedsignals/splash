# The frame — turning 40 pieces of feedback into work

Read `FEEDBACK-2026-08-10.md` for the feedback itself and the owner's two rulings; read
`survey/*.md` for where each item lives, measured. This file is the frame the specs are written
inside: the order, the invariants nobody may break, and what blocks what.

## The method, restated because it decides every answer below

The twin is Tom Vaillant's self-contained-skill method. **A skill stays copy-pasteable on its own,
so helpers are duplicated rather than imported** — enforced by `no-cross-skill-imports.test.ts`.

So no spec below may answer "make this true for 23 types" with a shared module. The twin's form of
that answer is always: **the same change, made identically in each craft skill, with a WALKING
parity test proving the copies stay in step.** `render-still-parity.test.ts` and
`video-helper-parity.test.ts` walk the tree and compare function by function, so a new copy is
guarded the moment it lands. `helper-parity.test.ts`'s hand-written list is the standing
counter-example: it turned the suite red for a *correct* change, and two agents kept a dead export
alive to satisfy it.

A spec may argue that some item needs a different home. It must **argue** it against this rule, with
evidence. It may not assume it.

## Four invariants no spec may trade away

1. **Nothing renders in a colour, a value or a default nobody chose.** A missing input throws and
   names what it looked for.
2. **Every number a reader sees is derived from the beat's own frozen data**, never typed. Guarded
   by `claims-grounded-in-data.test.ts`, whose blind spots are stated in its own header.
3. **A beat's inputs and outputs live in the beat's own folder.** Guarded by
   `render-output-lands-in-its-own-beat.test.ts` and the provenance half of the grounding guard.
4. **A guard that cannot go red is worse than no guard.** Every new guard ships with the mutation
   that reddens it, run in a copy outside the tree.

## The order, and why

Two things gate everything else and must land first.

**W1 blocks the journey.** Every other journey item is a conversation the tool has with a
journalist; W1 fixes *what the tool is allowed to say*, and two of its items are outright defects
producing false statements — a takeaway wrongly refused, and a gate reporting `production` on a
storyboard another gate refused.

**W2 blocks every visual chantier.** The palette reaches 15 of 70 beats and **zero of 11 skill
seeds**. A seed is what a new beat is copied from. Fixing beats without fixing seeds means the
defect regenerates on the next beat — the owner's own feedback→system rule. Nothing else touching a
component should land before the seeds are right, or it will be re-done.

Then, in leverage order, independent of each other:

| # | Chantier | Why here |
|---|---|---|
| W1 | The journalist's journey | Blocks the journey; contains two false-statement defects |
| W2 | Palette to the seeds, and credits at the bottom | Blocks every visual chantier; the seed is the multiplier |
| W3 | The seven visual mechanisms | 19 owner items; one idiom alone is 13 sites |
| W4 | Three export sizes, and web as a range | Ruling R2; cheapest in video, dearest in maps |
| W5 | The map camera | Largest single piece; the camera is decided 16 times |
| W6 | Map web on live MapTiler | Ruling R1; overturns a written decision |
| W7 | Typeface | Dearest per item; needs a font-provisioning answer first |
| W8 | flow/route × web | The one empty matrix cell; needs W3's hoverable line |

**W5 and W6 overlap heavily** (both rewrite how a map web beat is built) and W4's map half depends
on W5's camera. Spec them together or sequence them; do not run them as three independent chantiers.
**W8 needs W3's hoverable-line primitive** — build it once, it closes the slope's missing hover too.

## What must be settled before its spec can be written

- **W7 (typeface)** cannot be specified until two things are measured, and neither has been:
  does `fontFiles` work on the pinned `@resvg/resvg-js ^2.6.2`, and does Remotion 4.0.507 pick up an
  in-composition `@font-face`? A house face must reach resvg, headless Chrome **and a stranger's
  browser**, and the standalone HTML has no `@font-face` today. There is also a licensing question
  nobody has asked. **Measure first, spec second.**
- **W4's map half** waits on W5: the target aspect has to become an input the camera takes.
- **B6.11 vs the frame-0 guard** looked like a contradiction and is not. The guard requires frame 0
  non-empty; the owner requires the map field empty at 0:00. Both hold if **title and source render
  at full opacity from frame 0 and the field is empty** — exactly what the chart videos already do
  and the map videos never received. Settled; no ruling needed.

## Two owner observations the surveys could not reproduce

Recorded because this project's rule is that any report can be wrong, including the owner's.

- **The slope's connecting lines ARE rendered** — 10 `<line>` elements, 9 dark runs measured in a
  pixel column. What is genuinely missing is the two vertical axes, which `types/slope.md:37`
  requires by name. The observation was right that something is absent; the diagnosis moves.
- The histogram's overlapping labels start at **frame 154**, not 150.

## What every spec must contain

Same shape, so they can be executed in parallel by people who have not read each other's:

1. **The measured state** — file:line, counts, what is true today.
2. **The change, per craft skill**, named file by file. If it is duplicated, say into how many
   copies.
3. **The walking guard** that keeps the copies in step, and **the mutation that reddens it**.
4. **What it does NOT close** — every spec names its own residue.
5. **The proof** — which artifact gets re-rendered and opened, at which sizes, and what would be
   looked at. Not "tests pass": an opened artifact.
